# Hydra

Hydra is an existing dual-boot desktop. It does not need installation or disk
provisioning. The initial configuration uses the repository's locked unstable
nixpkgs while preserving the installed system's `system.stateVersion = "26.05"`.
Home Manager is initialized separately with state version 26.05.

## Disk boundary

| Owner | Model | Serial | Use |
| --- | --- | --- | --- |
| NixOS | AGI512G44AI818 | AGIPEFWWK0402177 | Root and NixOS EFI partition |
| Windows | Samsung SSD 970 EVO Plus 500GB | S4EVNM0T800393E | Entire disk excluded from NixOS management |

The Windows disk's WWN is `eui.00253858219028c4`. Never mount, format,
repartition, repair, or install boot files on that disk or its partitions.
NVMe numbering is not stable and must not be used to identify ownership.

NixOS filesystems:

- `/`: UUID `db4ff489-583a-46ef-8de8-700cdde7ee4d`, ext4.
- `/boot`: UUID `DD0E-90AB`, FAT, on the NixOS disk.

Only these UUIDs are permitted by Hydra's filesystem assertions. There is no
disk swap. Udev hides the Windows disk and its partitions from UDisks desktop
mounting; this does not prevent a privileged manual mount, which is prohibited.

Systemd-boot manages only the NixOS EFI partition. EFI variable writes are
disabled to preserve existing firmware entries. Microsoft EFI files already
present on the NixOS EFI partition must also be preserved. Choose Windows
through the existing boot menu or firmware menu.

## Initial environment

- Two Xeon E5-2699 v3 CPUs, 36 cores / 72 threads, approximately 110 GiB RAM.
- RTX 3060 with NVIDIA open kernel modules and DRM modesetting.
- Niri, Dank Material Shell and greeter, Xwayland Satellite, Nautilus,
  desktop portals, PipeWire and WirePlumber.
- Ghostty, Zellij, Firefox, Git, Neovim, direnv, Nix tools, Podman, and nix-ld.
- Obsidian installed without configured vaults. Add vault imports or settings
  in `hosts/hydra/home.nix` when the working directories are chosen.
- One Xiaomi Mi Monitor connected over both DisplayPort and HDMI.
  `hosts/hydra/monitor.nix` selects 3440×1440 at 144 Hz, scale 1, over
  DisplayPort and disables the duplicate HDMI output in Niri. Both the greeter
  and Home Manager use this host-specific configuration. Outputs match the
  EDID make/model/serial names, not connector numbers: DisplayPort reports
  `Xiaomi Corporation Mi Monitor Unknown`, while HDMI reports
  `Xiaomi Corporation Mi Monitor 0000000000000`. DMS output includes are
  disabled on Hydra so generated settings do not override the declared mode.

No laptop PRIME settings, laptop power management, full Andromeda application
list, VPN profiles, private keys, or account sessions are copied.

## Keyboard shortcuts

Hydra imports `modules/home/desktop/niri-keybinds.nix`. The baseline shortcuts
are declared through Home Manager and work even when DMS's generated
`dms/binds.kdl` is empty in a fresh profile. Custom bindings generated by DMS
can override matching keys. Andromeda keeps its existing bindings.

`Mod` is the Super/Windows key in the desktop session.

| Shortcut | Action |
| --- | --- |
| Win+T or Win+Enter | Open Ghostty |
| Win+Space | Application launcher |
| Win+Q | Close focused window |
| Win+arrows or Win+H/J/K/L | Focus adjacent column/window |
| Win+Shift+arrows | Move column/window |
| Win+D or Win+Tab | Toggle overview |
| Win+1…9 | Focus workspace |
| Win+Shift+1…9 | Move column to workspace |
| Win+F / Win+Shift+F | Maximize column / fullscreen |
| Win+Alt+L | Lock screen |
| Win+Shift+/ | Show shortcut help |
| Print / Ctrl+Print / Alt+Print | Capture area / screen / window |

Keyboard volume and microphone mute keys use WirePlumber's current default
devices. These bindings also work while the session is locked.

## Cursor

Hydra uses Adwaita cursors at 24 px through `home.pointerCursor`; Niri reads
the same theme and size. GTK 3/4, Xcursor environment variables and Xresources
are configured consistently. The theme is installed and linked into the
user's icon search paths. This fixes the missing `default` cursor theme
reported by Niri on the fresh profile (`no default icon`), which caused it to
use its fallback cursor. Display scale remains 1.

## Access and deployment

The bootstrap address is `192.168.8.129` over Wi-Fi. NetworkManager keeps the
existing connection. The declared hostname is `hydra`; DNS/DHCP naming is
managed separately on the router.

A dedicated SSH public key is declared for `p47hf1nd3r`. Its private key on
Andromeda is `~/.ssh/hydra-p47hf1nd3r`; it is not in this repository.
Password login remains enabled during bootstrap; root SSH login is disabled.
The existing user's password is retained, not stored in Nix files.

```sh
ssh -i ~/.ssh/hydra-p47hf1nd3r p47hf1nd3r@192.168.8.129
```

To use that key with the deployment recipe:

```sh
NIX_SSHOPTS="-i $HOME/.ssh/hydra-p47hf1nd3r" just rebuild switch hydra 192.168.8.129
```

Build, inspect activation, then stage the new kernel and driver for a reboot:

```sh
nix build --no-update-lock-file --no-link path:.#nixosConfigurations.hydra.config.system.build.toplevel
just rebuild dry-activate hydra 192.168.8.129
just rebuild boot hydra 192.168.8.129
```

Retain the original system generation and `/etc/nixos` until the new system
has booted successfully. During bootstrap, source files are copied into
`~/Workspaces/nixos-configurations`, without private keys or `.git` internals.

After boot, check SSH, `nvidia-smi`, `systemctl --failed`, the greeter, user
login, monitor configuration, audio, and screen sharing. GUI login and
application authorization require the user's session.

If the new generation cannot boot, select the previous NixOS generation from
the boot menu. To restore the previous system profile from a working NixOS
session, use `sudo nixos-rebuild switch --rollback`.

## Deployment verified on 2026-10-05

The system was built, copied over SSH, staged with `boot`, and rebooted. The
Ghostty configuration was then adjusted to use its built-in Adwaita Dark
theme on a fresh home directory; Andromeda explicitly keeps its generated
`dankcolors` theme. The corrected generation was activated successfully.

Verified on Hydra:

- Hostname `hydra`, kernel 6.18.53, SSH key login after reboot.
- NVIDIA driver 595.99.02 reports RTX 3060 with 12288 MiB VRAM.
- Greetd and the Niri greeter compositor are running.
- User login starts Niri and DMS successfully. After fixing the fresh-profile
  shortcut gap, Niri reloads the declared keyboard bindings in the running
  session without requiring logout.
- Home Manager activation and Ghostty configuration validation succeed.
- No failed system or user services.
- The greeter compositor reports one active output at 3440×1440 @ 144.000 Hz,
  scale 1, position 0,0, over DisplayPort. The duplicate HDMI output is
  disabled. Matching monitor settings are activated for the user session.
- The Windows disk and all four partitions have `UDISKS_IGNORE=1` and
  `UDISKS_AUTO=0`; none is mounted.
- Microsoft EFI files on the NixOS EFI partition retain their original
  SHA-256 checksums, recorded in `/var/lib/hydra-bootstrap`.

Local validation included a full Hydra build, `nix flake check --no-build`,
Niri configuration validation, formatting, and recipe dry runs. Andromeda and
Corvus evaluate to the same system derivations as before the refactor.
`flake.lock` is unchanged. Existing boot generations and the original
configuration remain available for recovery.

In the active user session, PipeWire and WirePlumber expose the Intel PCH
analog stereo output/input and the NVIDIA display audio output. A short PCM
playback test connects, streams, and drains successfully; physical audibility
was confirmed by the user on 2026-10-06, along with working keybindings.
Adwaita cursor configuration was also applied in the running Niri session
without restarting the compositor. The desktop portal exposes ScreenCast version 5
and successfully opens the monitor selection dialog and returns a 3440×1440
PipeWire stream. Receipt of video frames is not yet verified: the initial
diagnostic consumer reported a target lookup error, and a repeat using the
node's stable serial timed out waiting for monitor selection. No screen
recordings were saved.
Vaults and additional work applications are deferred.
